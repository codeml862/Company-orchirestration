# Session 2026-10-28

Everything built in this session, and everything still to do. Orchestria (formerly AICO) is a platform
where a company of AI agents takes a client project from request to delivery.

## How to run it locally

Backend (from the project folder; reloads on code and `.env` changes):

```bash
uv run --directory backend uvicorn app.main:app --reload --reload-include .env --port 8000 --timeout-graceful-shutdown 3
```

Frontend:

```bash
npm --prefix frontend run dev
```

Worker (runs the agents; needs an LLM provider in `AICO_LLM_PROVIDERS`):

```bash
uv run --directory backend python -m app.worker
```

- App: http://localhost:3000 · API docs: http://localhost:8000/docs
- Admin login: whatever `AICO_BOOTSTRAP_ADMIN_EMAIL` / `AICO_BOOTSTRAP_ADMIN_PASSWORD` say in `backend/.env`.
  The API applies them on every start (see "Admin login" below).
- Database: SQLite file `backend/data/aico.db`. Apply migrations with
  `uv run --directory backend alembic upgrade head`.

## Done today

### Running locally on SQLite
- The backend runs on SQLite for local development (PostgreSQL stays the choice for production and
  docker-compose). Changes: portable JSON and UUID column types, UTC-aware timestamps, a SQLite engine that
  serializes writes (`BEGIN IMMEDIATE`), a portable metrics query, and a SQLite fallback for the agents'
  `knowledge.search` tool.
- Agent tool runs no longer hold a database transaction open while they execute (a 5-minute sandbox run
  used to block every other write on SQLite).
- The test suite runs on SQLite too: set `AICO_DATABASE_URL=sqlite:///<file>` and run `pytest`.

### Product name
- AICO is now **Orchestria** everywhere people see it (UI, API docs, agent prompts, README). Internal names
  stay: the `AICO_` settings, the database name, and the `aico.token` / `aico.user` browser storage keys.

### UI redesign (all staff pages)
- New shared pieces: stat tiles with icons, agent avatars, search box, department icons, data-freshness
  indicator ("Updated 12s ago" / "Couldn't refresh"), full-page error with retry, form dialog shell.
- Redesigned: Executive Dashboard, Departments, Agent profile (Overview / Configuration / Activity, with
  validation, unsaved-changes bar and conflict warning), Organization, Live Operations, Supervisor Console
  (retry/cancel exceptions, inline budget edits), Projects, New Project (drag-and-drop files, step progress,
  no duplicate project on retry), Clients & Users, Agents (grouped cards, no horizontal scroll).
- Sidebar: original colors, rounded card with border, header aligned with the page header, pending-approvals
  badge, pointer cursor on every clickable element.
- Real error handling in the API client and data hook: network / permission / not-found / server errors get
  clear messages; failed refreshes keep the last data; polling pauses in hidden tabs.

### Organization
- `AICO_ENABLED_DEPARTMENTS` limits the company to some departments. Currently: executive, operations,
  technology (27 agents). An invalid choice (one that can't run the workflow) is rejected with a clear error.
- Admins can grow the company from the app: **Add department** (switch on a ready-made catalog team, or
  create a custom department) and **Create agent** (any role, with hierarchy rules enforced). Departments
  added in the app survive later catalog syncs.
- **Company-built agents**: client companies create their own specialists on the portal ("My Agents").
  They join one department's team, only ever work on that company's projects, never act as QA reviewers,
  and their work goes through company QA.

### Feature 1 of 9: Autonomy engine (autopilot)
- Each client has an autonomy level: `supervised` (people decide everything), `autonomous` (default for new
  clients), or `full`.
- The worker runs the autopilot every 10 seconds. Policy:
  - Client clarification: waits 24h for the client, then the agent proceeds with stated assumptions.
  - Budget overrun: up to 2 extensions per task and 2 per project, then a person decides.
  - Final delivery: released only if the objective and every outcome are met and no work task failed;
    otherwise sent back to the CEO for revision (up to 2 rounds), then to a person.
  - External action, spending, hiring: a person at `autonomous`, the autopilot at `full`.
  - Production changes and irreversible actions: always a person.
- Every decision is in the audit log; escalations show the reason on the approval card.
- Only supervisors and admins can change a client's autonomy level. `python -m app.cli autopilot` runs one pass.

### Company Graph (new sidebar page)
- Network view on a white background: every agent is a profile avatar (initials, team color, status dot,
  name). Each team has its own color.
- Lines: reports to, same team, and "worked together" (from real task assignments and QA reviews).
- Hover an agent: its connections light up and pulses travel along them; from the CEO the pulses cascade
  down the reporting lines. Drag nodes, Ctrl + scroll to zoom, click for details.

### Account
- Profile menu under your name: **Profile**, **Settings**, **Help & support**, Sign out.
- Profile: edit your name; account details. Settings has a left section menu: **General** (start page,
  collapsed sidebar), **Notifications** (desktop alerts for new decisions / client questions), **Security**
  (change password, session expiry, sign out). Help: getting started, concepts, FAQ, shortcuts, live system
  status.

### Admin login from `.env`
- `backend/.env` owns the first admin account: on every start the API applies `AICO_BOOTSTRAP_ADMIN_EMAIL`
  and `AICO_BOOTSTRAP_ADMIN_PASSWORD` (creates the admin, or updates its email and password). A password
  changed for this admin in the app is reset to the `.env` value on the next restart.

### Smaller fixes
- `http://localhost:8000/` now answers with the API status instead of `{"detail": "Not Found"}`.
- Dialogs: the client dialog fits the screen and dialog footers are no longer cut off.
- Page refresh no longer waits on "Loading…": the signed-in user is cached and the session is re-checked in
  the background. A server that is restarting shows "Can't reach Orchestria · Try again" instead of logging
  you out; only an expired session signs you out.

## Still to do

### Fix before real users (from the code review)
1. **Account takeover via sign-up**: sign-up never verifies the email, and Google sign-in signs into any
   account with that email. Add email verification (or block Google sign-in into unverified accounts).
2. **No rate limiting** on login, sign-up and Google sign-in.
3. **Login token in the live-stream URL** (`/api/events/stream?token=...`) ends up in access logs. Use a
   short-lived stream ticket instead.
4. **Downloads crash on non-English file names** (e.g. Telugu): use an RFC 5987 `filename*` header.
5. **docker-compose is not production-ready**: Postgres exposed on 5432 with password `aico`, no HTTPS, and
   no working code sandbox inside the containers.
6. Web fetch SSRF check can be bypassed with DNS rebinding; no Content-Security-Policy header; dollar budgets
   never trigger unless model `prices` are configured; projects list makes extra queries per project;
   deleting a project removes files before the database commit.

### Features 2 to 9 (one at a time)
